# Compiler and CI assumptions

Foundry pins Solar and Solc in `foundry.toml`. Forge prints Solar's Solidity compatibility
version during compilation. The profile pins the actual Solar release. All profiles target Prague.

- Ordinary jobs use the Solar default with the optimizer disabled. They compile independently
  without GitHub artifact transfers or compiler-cache restore. Local development still uses
  Forge's incremental cache under `cache-solar/` with artifacts under `out-solar/`.
- Deployment, verification, and canonical gas snapshots use the Solc release profile with the
  optimizer enabled at 400 runs. Solar's generated bytecode can differ in size, gas, and deployment
  addresses. Use the deploy wrappers when a script produces contract creation bytecode.
  Verify already deployed contracts from their original source revisions.
- Deprecated tests also use the default compiler. To reproduce a result with the release compiler,
  run `FOUNDRY_PROFILE=deploy forge test …`. Its optimizer settings apply uniformly to the graph.
- Kernel, minting, staking, role management, and bridge operations use the default compiler. Their
  scripts encode calls to existing contracts. The chain executes the bytecode already deployed.
- Proposal simulation and input printing use the default compiler. Set `FOUNDRY_PROFILE=deploy`
  for those commands when a proposal constructs contracts locally and you need its creation
  bytecode or derived addresses to match the release build. Proposal submission uses `deploy`.
- Safe batch wrappers use `multisig`, which inherits Solar from `default` and disables isolation
  and script execution protection. Safe internal calls share one transaction funded by a relayer.
  Disabling Forge isolation avoids simulating each call as a separate transaction funded by the Safe.
  The wrappers encode calls to existing contracts, including on-chain factories that supply their
  own creation code. Run scripts that embed locally compiled creation code through the release
  tooling with `FOUNDRY_PROFILE=deploy`.
- Coverage inherits Solar from `default` and uses `--ir-minimum` with reduced fuzz and invariant
  budgets. Changing compilers can change source mappings and report totals. The Burner Loans
  external-routes fixture needs an active fork, so it runs through `pnpm run test:fork`.
  In a fixed-seed comparison, both compilers passed all 217 library tests. Solar reported
  48 of 70 branches covered in `src/libraries/`, and Solc reported 43 of 70.

## Size and gas checks

`pnpm run size` reuses the `deploy` profile's `out/` and `cache/` locally. Forge checks the sizes of
both freshly compiled and cached artifacts for the selected graph. CI runs this check on a fresh
runner without restoring a compiler cache. The roots include the production contracts and
`src/proposals/helpers/`. Forge includes their transitive imports.
Deployment scripts and simulation contracts have their own entry points. See the
[proposal guide](../src/proposals/README.md) for placing deployable proposal helpers.

Snapshot recording is opt-in. Use `pnpm run test:gas` or `pnpm run test:gas:sharded` to record the
canonical snapshots. The repository test wrapper requires the deploy profile and a pinned Solc
release before it runs with snapshot emission enabled. For a raw Forge snapshot command, select
the Solc deploy profile explicitly.

CI runs the six gas groups in series with a cache per group. Their Forge root exclusions bound
compilation while allowing imports to enter the graph. The positive test path filters assign each
case to its own group, including when an import loads a test contract from a different group.
`pnpm run test:gas:check` compares tracked snapshot changes and flags newly created files.
Gas, fork, cross-chain, and proposal jobs use RPC credentials from GitHub. The workflow skips
those jobs on untrusted fork and Dependabot pull requests.
